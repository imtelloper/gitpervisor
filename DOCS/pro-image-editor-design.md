## 0. 요구사항 재정의 — "figma 처럼 전문적으로"

Figma 파리티는 완료 판정이 불가능한 목표라 채택하지 않는다. 이 앱에서 "전문적"은 **네 개의 판정 가능한 문장**이다.

| # | 문장 | 현재 | 판정 방법 |
|---|---|---|---|
| **A1** | 프리뷰 픽셀 == 저장 픽셀 | **달성** | e2e 30 전반 · 30 (l-1~l-3)(m-1) 가림 누수 · 35 (c-1~c-4) 줌 |
| **A2** | 손이 예상한 대로 반응한다 | **미달** | 빈 곳 드래그가 no-op(`AnnotationLayer.tsx:392-396`), 커서 2종뿐(`:690-694`), 방향키 없음(`:538-597`), 드래그 중 수치 없음 |
| **A3** | 회전 상태에서 변형이 맞는다 | **깨져 있다** | `resizeObject`가 회전 AABB 배율을 회전 이전 좌표에 먹인다(§2.2 D-A) |
| **A4** | 실수로 닫아도 되돌릴 수 있다 | **미달** | 닫으면 벡터 소실. 되돌릴 수단 0 |

**A2·A3만이 "전문 도구 같지 않다"의 실제 내용이다.** A3은 기능 요청이 아니라 **현존 결함 신고**다.
A4는 "세션 안"과 "세션 사이"로 갈리는데, 이 설계는 **세션 안만** 푼다(§4·§8).

측정 불가한 목표는 목표가 아니다 — 아래 어느 항목도 "Figma에 있으니까"를 근거로 삼지 않는다.

## 1. 결론 — 3줄

1. **새 파일 0개 · Rust 0줄 · 신규 의존성 0개 · 총 ≈190줄.** 손대는 파일은 `AnnotationLayer.tsx`,
   `geometry.ts`, `ImageEditor.tsx`, `render.ts` 넷뿐이고 `renderScene` 단일 렌더러와 `oriented px`
   단일 좌표계 계약은 한 글자도 바뀌지 않는다.
2. **레이어 패널·그룹·블렌드·효과·수치 패널·좌표계 재작성은 전부 넣지 않는다**(§8). 그 자리에
   회전 리사이즈 수정 · 마퀴 선택 · 핸들 커서 · 방향키 nudge · 드래그 중 수치 HUD가 들어간다.
3. **문서 영속은 사다리 아래 칸부터 낸다** — 창 수명 동안의 모듈 Map + "이어서 하기" 배너(≈35줄).
   해시·직렬화·스키마 버전·localStorage 쿼터 경쟁이 전부 필요 없고, 세션 간 영속은 요청이 오면 그 위에 얹는다.

## 4. 문서 모델과 영속

### 4.1 스키마 — 바뀌지 않는다

`EditorDoc`(`types.ts:140-151`)에 필드를 **추가하지 않는다.** 직렬화하지 않으므로 `v` 버전 필드도,
`parseDoc` 파서도, 마이그레이션 체인도 없다. 미지 `kind` 처리 규칙도 필요 없다 —
문자열을 거치지 않고 객체가 그대로 살아 있기 때문이다.

> 참고: 세션 간 영속(§8 보류)으로 올라갈 때 비로소 필요해지는 것들이다. `geometry.ts`의
> exhaustive switch는 `:198 :241 :281 :359 :374`에 더해 `transformObjects:475`(default 없음)와
> `translateObject:520`까지 **7곳**이므로, 그때는 미지 kind를 통과시키면 안 된다.

### 4.2 저장 위치 — 창 수명 모듈 Map

```ts
// ImageEditor.tsx 모듈 스코프
// ponytail: 창 수명 동안만 산다. OS 창을 닫으면 사라진다 —
//           세션 간 복구가 필요해지면 localStorage(키당 항목)로 올린다(§8).
const stash = new Map<string, EditorDoc>();   // 상한 8, 넘으면 가장 오래된 키 삭제
const stashKey = (pid: string, path: string) => `${pid}\u0000${path}`;
```

| 시점 | 동작 |
|---|---|
| `requestClose` → `close()` 직전 | `doc.objects.length`면 `stash.set(key, docRef.current)` |
| 로드 성공 직후 | `stash.has(key)`면 배너 표시. **문서는 건드리지 않는다**(K7) |
| 배너 [이어서 하기] | `applyDoc(stashed, "commit")` — **문서 통째 교체** |
| 배너 [버리기] | `stash.delete(key)` |
| 저장 성공(`writeTo` onSuccess) | `stash.delete(key)` |

**복원이 `applyDoc` 통째 교체여야 하는 이유**: 직렬화된 objects는 "그 rotation/flip이 이미 적용된
공간"의 값이다. `patchDoc({rotation})`으로 넣으면 `transformObjects` 델타가 두 번 걸린다 —
`ImageEditor.tsx:398-399`에 "예전처럼 oriented 변경 효과에 얹으면 델타가 두 번 걸린다"고
**한 번 당한 기록이 주석으로 남아 있는** 그 자리다. `applyDoc`은 `transformObjects`를 아예 부르지
않으므로(회전은 `rotateBy`/`flipBy`에서만 델타를 건다, `:405-436`) 구조적으로 안전하다.

**저장 성공 시 삭제가 이중 주석을 막는다.** 저장하면 파일에 픽셀이 구워지므로, 그 파일을 다시
열었을 때 같은 objects를 복원하면 주석이 두 겹이 된다. 삭제 한 줄이 그 실패 클래스를 통째로 없앤다.

### 4.3 마이그레이션 — 없다

프로세스 메모리 안의 객체라 포맷이 없다. 앱을 재시작하면 stash가 사라지는 것이 곧 무효화다.

### 4.4 동시편집 · 원본 변경 감지

**이 설계는 둘 다 다루지 않는다.** `openDocWindow`는 호출마다 새 uuid를 만들어(`floating.ts:93`)
같은 파일에 창을 여러 개 열 수 있고, 각 창의 스토어는 완전히 독립이다(`DocWindow.tsx:42-44` —
명시된 전제). 나중에 저장한 쪽이 상대를 조용히 덮는다.

편집 창 단일화(`getByLabel('doc-<id>').setFocus()`)를 검토했으나 §8로 내렸다 — DocWindow의
편집기 자동 오픈은 **창당 1회**이고(`DocWindow.tsx:53-61`, `target`이 docId로만 메모),
저장 성공 시 편집기는 스스로 `close()`해(`ImageEditor.tsx:647`) 그 창은 뷰어로 돌아간다.
즉 focus만으로는 뷰어만 앞으로 오고, 그 창에 "편집기를 열어라"를 전달할 채널이 추가로 필요하다.
15줄로 끝나지 않는다.

원본 변경 감지도 넣지 않는다. 저장 직전 최대 25MB를 되읽어 해시하는 비용 대신, 근본 결함인
`write_file_bytes`의 무검사 덮어쓰기(§2.2)를 **Rust 쪽에서 `expected_mtime` 인자 하나로**
고치는 것이 더 싸고 원자성에도 가깝다 — 별도 커밋(§8).

## 7. 단계 계획

각 단계는 **그것만 머지해도 출시 가능**하다. 순서는 `AnnotationLayer.tsx`(1,106줄) 한 파일에
세 축이 겹치지 않게 직렬화한 것이다.

> **2026-09-03 · Q0 답변 반영 — 순서를 바꿨다.** 사용자가 꼽은 것은 "조작감이 아마추어 같다"
> 였다(회전 결함도, 소실도 아니다). 그래서 **P0 → P2 → P3 → P1 → P4** 로 간다.
> P1(회전 리사이즈)은 유일하게 확인된 결함이라 여전히 P4보다 앞이지만, 도달 경로가
> "이미지를 90° 돌린 뒤 텍스트/뱃지를 리사이즈"라는 좁은 조합이라(§2.2 D-A) 사용자가
> 매일 겪는 D-B·D-C·D-D 뒤로 보낸다. 단계 내용과 수용 기준은 그대로다.
>
> 같은 답변에서 **범위 밖 데이터 손실(§2.2 말미의 `write_file_bytes` 무성 덮어쓰기)을
> 먼저 고치기로 했고, 그것은 이미 반영됐다** — 아래 §7.0 참조.

### 7.0 — (완료) 무성 덮어쓰기 차단

설계 승인과 무관한 독립 결함이라 먼저 처리했다. `read_file_base64` 가 `stamp`
(`"<mtime_ms>:<len>"`)를 함께 주고, `write_file_bytes` 가 `expected_stamp` 를 받아
쓰기 직전 이미 뜬 `symlink_metadata` 로 대조해 다르면 새 `Conflict` 코드로 거절한다.
편집기는 **제자리 저장에서만** 스탬프를 붙이고(다른 이름으로 저장은 대상이 다른 파일이다),
CONFLICT 를 받으면 "외부에서 변경됨" 확인을 띄운 뒤 스탬프를 빼고 재시도한다.

- 파일을 되읽지 않는다(이미 뜬 메타만 쓴다) — 저장 비용 증가 0.
- `expected_stamp` 생략 = 종전과 1비트도 다르지 않다(변환 저장·e2e 기존 호출부 무영향).
- mtime 을 못 얻는 파일시스템에서는 검사를 포기하고 통과시킨다(기능이 죽는 것보다 낫다).
- 회귀: e2e 15 에 4개 단언(스탬프 존재 / 일치 통과 / 불일치 CONFLICT / 생략 시 종전 동작).

### P0 — 위생 (기능 0, ≈12줄 / 2파일)

`releaseScratch()` + 입력 크기 게이트.

**수용 기준**
- e2e 30·34·35 전부 기존 그대로 통과(기준선 대비 pass 수 동일).
- 편집기를 열었다 닫은 뒤 `window.__gpv` 경로에서 스크래치 참조가 null(개발자 확인 1회로 충분 —
  e2e 단언 대상 아님).
- 한 변 16384 초과 이미지를 열면 **에러 메시지가 뜬다**(빈 화면 아님).

## 부록 — 구현 기록 (2026-09-03)
