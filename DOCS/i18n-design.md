# 다국어(UI 언어) 지원 설계

> 상태: **P0~P5 구현(i18n 브랜치, 2026-09-22) — 남은 것은 태스크 72와 겹친 파일뿐(§11).** §10은 권장안으로
> 확정 — 영어 먼저, 기본 `"system"`, 이행 중 영어는 "베타" 표시로 공개, 로그는 사용자 언어, 웹사이트는 범위 밖.
> 용어집은 `DOCS/i18n-glossary.md`.
> 이 문서는 "UI를 여러 언어로 보여 주기"만 다룬다. 이미 있는 **AI 출력 언어**(`llmLanguage`)와
> LLM 번역 기능(`TranslateCard`)은 별개이며 그대로 둔다(§4.6).

## 0. 한 줄 결정

| 항목 | 결정 |
|---|---|
| 대상 언어 | 한국어(원본) + 영어. 구조는 언어를 더할 수 있게 — 추가 시 컴파일러가 빠진 번역을 전부 가리킨다 |
| 라이브러리 | **새 의존성 없음.** 도메인별 TS 모듈에 언어별 문구를 나란히 두고, 타입으로 완전성을 강제한다 |
| 접근 | `const msg = useMessages(); msg.changes.showMoreRows(n)` — 문자열 키·런타임 조립 없음 |
| 설정 | `uiLanguage: "system" \| "ko" \| "en"`(기본 `"system"`). OS 언어 판정은 **Rust 한 곳**에서 |
| Rust 문구 | Rust가 스스로 번역한다 — `Lang` 전역 + 메시지 함수(전 언어 `match` 강제). `IpcError` 구조 불변 |
| 번역 안 함 | 로그·코드 주석·DOCS·e2e 라벨·git 출력·사용자 데이터·LLM 프롬프트 |
| 검증 | ① 컴파일러(키·인자·언어 누락) ② 소스 스캔 가드(이행 끝난 곳에 한글 리터럴 재유입 금지) ③ 영어 스윕 e2e(화면에 한글이 남으면 빨강) |
| 이행 | 6단계(P0~P5). 기존 e2e는 한국어로 고정해 단언 249줄을 그대로 쓴다 |

## 1. 범위

**번역한다**
- 프런트 UI 문구 전부: 버튼·라벨·툴팁·placeholder·토스트·확인 대화상자·빈 상태·설정 화면·검색 색인 라벨.
- Rust가 **사용자에게 보여 주는** 문구: IPC 오류 메시지, health 경보 사유(배너), OS 알림(AI 작업 완료·외부 알림 제목), 창 제목(`터미널`·`리소스 모니터`·`터미널 모아보기`·`화면 캡쳐`).
- 날짜·시간·숫자·용량 표기(`relativeTime`·`shortDate`·`formatBytes`·`toLocaleString` 9곳·리포트 기간 라벨 `9월 1주`·잔디 요일).
- Windows 설치 프로그램(NSIS) 언어 — 지금 `languages: ["Korean"]`.

**번역하지 않는다**
- `Gitpervisor.log`(진단용 — `[term-perf]`·`[health]` 판독표가 필드명으로 읽는다), 코드 주석, `DOCS/`, e2e `r.check` 라벨.
- git·셸·외부 도구가 내는 원문(`stderr`), 커밋 메시지·파일명 등 사용자 데이터.
- LLM 프롬프트(`report.ts` `DEFAULT_REPORT_PROMPT`, 번역 프롬프트) — 모델 입력이지 UI가 아니다. 출력 언어는 `llmLanguage`가 정한다.
- 웹사이트(`website/`, 별도 Next.js) — 필요하면 별도 설계.

## 3. 원칙 — 이 저장소의 코드 규칙과 맞물리는 지점

CLAUDE.md「코드 규칙」의 세 기준(grep 한 번에 찾히는가 · 필요한 부분만 고칠 수 있는가 · 틀리면 컴파일러가
잡는가)을 i18n에 그대로 적용하면 흔한 방식 대부분이 걸러진다.

1. **키를 문자열로 두지 않는다.** `t("changes.showMore")`는 오타가 런타임 `undefined`로만 드러나고,
   `t(\`${area}.title\`)` 같은 조립이 쉬워 호출처가 검색에서 사라진다("식별자를 런타임에 조립하지 마라").
   → 객체 경로 접근 `msg.changes.showMoreRows` — 없는 키는 tsc 오류.
2. **보간·복수형은 함수로.** `showMoreRows: (hidden: number, step: number) => ...` — 인자 개수·타입이
   컴파일러에 걸린다. 한국어엔 복수가 없고 영어엔 있으므로 언어마다 함수 몸통이 다르다(§4.2).
3. **언어 누락은 컴파일 오류.** 언어 목록(`Locale` 유니온)에 하나를 더하면 모든 도메인 파일이 그
   언어 번역을 요구하며 빨개진다. 런타임 폴백으로 "일단 뜨게" 하지 않는다.
4. **같은 개념은 같은 단어.** 앱 고유 용어(모아보기·잔디·메모장·탭 모으기·float 모드·패널 분리…)를
   용어집(`DOCS/i18n-glossary.md`)에 먼저 정하고 번역은 그걸 따른다.
5. **세 OS 모두.** 언어 판정·설치 프로그램·폰트가 Windows 전용이 되지 않게(§4.1, §4.5).

## 4. 설계

### 4.1 언어 설정과 판정

- Settings에 `ui_language: String`(`"system" | "ko" | "en"`, 기본 `"system"`) — Rust `git/types.rs`와
  TS `ipc.ts`를 **같은 커밋**에서. 설정 › 일반에 선택 상자, 검색 색인 항목(e2e 29 ⑤ 완전성 가드).
- `"system"` 판정은 **Rust 한 곳**에서 한다. 프런트가 `navigator.language`로 따로 판정하면 Rust(창 제목·
  오류)와 어긋날 수 있다 — Windows에서 표시 언어(영어)와 지역 형식(한국)이 다른 사용자가 흔하다.
  - Windows: 표시 언어 `GetUserPreferredUILanguages`(지역 형식 `GetUserDefaultLocaleName`이 아니다).
  - macOS: `NSLocale.preferredLanguages`(objc2-foundation은 이미 트리에 있다).
  - Linux: `LANGUAGE` → `LC_ALL` → `LC_MESSAGES` → `LANG`.
  - `sys-locale` 크레이트가 이 셋을 위 기준대로 구현하는지 **실기 확인 후** 채택, 아니면 직접(각 20줄 안팎).
  - 판정 결과가 `ko`로 시작하면 `ko`, 그 외 전부 `en`.
- 판정 결과는 IPC `ui_language_resolved() -> "ko" | "en"`로 프런트에 준다. 프런트는 이 값만 쓴다.
- **첫 화면 깜빡임 방지**: 각 창의 진입점(`main.tsx`의 메인·doc·플로팅·리소스 모니터 분기)이 `createRoot`
  전에 이 IPC 한 번을 기다려 언어를 정한다(로컬 IPC 수 ms). 안 그러면 영어 사용자가 매번 한국어 화면을
  한 프레임 본다.
- 창 간 동기화: 설정 저장은 이미 `settings://changed`를 모든 창에 쏜다(`commands/settings.rs`) —
  각 창이 그 이벤트에서 언어를 다시 적용한다. 재시작 불필요.

### 4.2 프런트 카탈로그

**배치 — 도메인 파일 하나에 언어를 나란히.** 번역이 원문 옆에 있어야 문구를 고칠 때 다른 언어를 같이
보고 고친다(언어별 파일로 가르면 한쪽만 고치는 표류가 생긴다). 도메인 단위라 여러 세션·에이전트가
나눠 옮겨도 같은 파일을 두고 부딪히지 않는다.

```ts
// src/i18n/text-changes.ts — 파일명은 저장소에서 고유하게(text-<도메인>.ts)
const ko = {
  panelTitle: "Changes",
  showMoreRows: (hidden: number, step: number) =>
    `${fmtInt(hidden)}개 더 있음 — ${fmtInt(step)}개 더 보기`,
  discardConfirm: (path: string) => `'${path}' 의 저장되지 않은 변경을 되돌립니다. 복구할 수 없습니다.`,
};

export const changesText = defineText(ko, {
  en: {
    panelTitle: "Changes",
    showMoreRows: (hidden, step) => `${fmtInt(hidden)} more — show ${fmtInt(step)}`,
    discardConfirm: (path) => `Discard unsaved changes to '${path}'? This cannot be undone.`,
  },
});
```

```ts
// src/i18n/define-text.ts
export type Locale = "ko" | "en";
/** 문자열 리터럴은 string으로 넓히고 함수는 시그니처를 유지한다 — 번역이 원문과 같은 모양이어야 한다. */
export type TextShape<T> = T extends string
  ? string
  : T extends (...args: infer A) => string
    ? (...args: A) => string
    : { [K in keyof T]: TextShape<T[K]> };

/** 한국어가 원본. 나머지 언어는 **전부** 요구한다 — Locale 에 하나를 더하면 모든 도메인이 빨개진다. */
export function defineText<K>(ko: K, others: Record<Exclude<Locale, "ko">, TextShape<K>>) {
  return { ko, ...others } as Record<Locale, TextShape<K>>;
}
```

```ts
// src/i18n/messages.ts — 도메인마다 한 줄. 단언 없이 도메인별 타입이 그대로 산다.
export function messagesFor(locale: Locale) {
  return { language: languageText[locale], changes: changesText[locale] /* … */ };
}
export type Messages = ReturnType<typeof messagesFor>;
```

- **접근**: React는 `useMessages()`(zustand 스토어 `useUiLanguage`의 `messages` 선택 — 언어가 바뀔 때만
  참조가 바뀐다), 컴포넌트 밖(스토어의 토스트·`lib/`)은 `currentMessages()`. 둘 다 **호출 시점의 언어**로
  문자열을 만든다 — 토스트처럼 저장해 두는 문자열은 만든 순간의 언어로 남는다(허용).
- **동적 접근 금지**: `msg[domain][key]` 형태는 쓰지 않는다 — 소스 스캔 가드가 `msg\[`·`Text\[` 패턴을 잡는다.
- **번들**: 두 언어를 정적으로 함께 싣는다. 문구 2,080개 기준 한국어 ~150KB·영어 ~60KB(gzip 전)로 로컬
  자산이라 비용이 없다. 언어가 셋 이상이 되면 그때 지연 로드(리터럴 경로 맵)로 바꾼다.
- **형식 헬퍼**(`src/i18n/format-locale.ts`): `fmtInt`·`fmtBytes`·`fmtRelative`·`fmtShortDate`·`fmtWeekday`를
  `Intl.*`에 현재 언어를 넘겨 만든다. `lib/format.ts`의 기존 함수는 이쪽으로 옮기고 호출처를 바꾼다.
  복수형은 `Intl.PluralRules`로 `plural(n, { one, other })` — 영어 파일에서만 쓴다.
- **설정 검색 색인**: `label`은 번역하고 `keywords`는 **두 언어 합집합을 그대로 둔다** — UI가 영어여도
  "프롬프트"로, 한국어여도 "prompt"로 찾힌다(지금도 키워드에 영어가 섞여 있다).

### 4.3 컴포넌트 이행 규칙

- 한 파일을 옮길 때는 **그 파일의 사용자 노출 한글을 전부** 옮긴다(반쯤 옮긴 파일은 가드가 못 지킨다).
- 문구를 조각내 이어 붙이지 않는다(`"총 " + n + "개"`) — 어순이 언어마다 달라 번역이 불가능해진다. 문장
  단위 함수 하나로.
- JSX 안의 굵게·링크가 섞인 문장은 함수가 `ReactNode`를 돌려주게 한다(`TextShape`에 `ReactNode` 반환 허용).
- `title`·`aria-label`·`placeholder`도 대상이다(눈에 안 띄어 가장 잘 빠진다 — 가드가 속성 문자열도 본다).

### 4.4 Rust 문구

**Rust가 스스로 번역한다.** `IpcError`에 키+인자를 실어 프런트가 번역하는 안은 기각했다(§9) — 창 제목·
OS 알림·health 사유처럼 IPC를 타지 않는 출력을 해결하지 못하고, 475곳의 오류 생성 지점을 구조째 바꾼다.

```rust
// src-tauri/src/i18n.rs
#[derive(Clone, Copy, PartialEq, Eq)]
pub enum Lang { Ko, En }
static LANG: AtomicU8 = AtomicU8::new(0);   // 설정 로드·저장 때 set_lang
pub fn lang() -> Lang { /* … */ }

// src-tauri/src/i18n/text_projects.rs — 도메인별 파일, 함수 하나 = 문구 하나
pub fn project_path_missing(path: &str) -> String {
    match crate::i18n::lang() {
        Lang::Ko => format!("프로젝트 경로를 찾을 수 없습니다: {path}"),
        Lang::En => format!("Project path not found: {path}"),
    }
}
```

- `match`가 모든 `Lang`을 요구하므로 언어를 더하면 **컴파일러가 빠진 번역을 전부** 가리킨다(TS의 §3-3과 같은 성질).
- 문구 함수는 매크로로 찍어내지 않는다(CLAUDE.md "함수를 찍어내는 매크로" 금지 — 호출처 검색이 끊긴다).
- `IpcError { code, message, stderr }`는 그대로. `message`만 현재 언어로 만들어진다. 프런트 `errorMessage(e)` 불변.
- 로그(`log::*`)는 번역하지 않는다. 오류를 로그에도 남기는 곳은 **로그용 한국어**와 **사용자용 번역**을
  따로 만들지 않고 사용자용 문구를 그대로 로그에 쓴다(영어 사용자의 로그는 영어가 된다 — 판독표는
  필드명으로 읽으므로 무관).
- 언어 적용 시점: `state.rs` 설정 로드 직후 + `set_settings` 저장 직후. 이미 떠 있는 창의 제목은 저장
  직후 `set_title`로 다시 쓴다.

### 4.5 설치 프로그램·폰트·배치

- `tauri.conf.json` `bundle.windows.nsis.languages: ["Korean", "English"]` + `displayLanguageSelector: false`
  (설치기가 OS 언어로 고른다). macOS dmg·Linux deb/rpm은 설치 UI가 OS 몫이라 할 일 없음.
- 폰트: 영어는 기존 스택으로 충분. 한국어 폰트 폴백은 그대로.
- **영어가 더 길다**(보통 1.3~2배). 툴바·상태바·탭 머리처럼 폭이 고정된 곳이 넘친다 — 영어 스윕(§5.3)이
  버튼·라벨의 `scrollWidth > clientWidth`를 보고, 단계마다 영어 화면 스크린샷을 한 번씩 눈으로 본다.

### 4.6 LLM 경계

- `llmLanguage`(AI 요약·번역의 출력 언어)는 UI 언어와 **독립**으로 둔다 — UI는 영어로 쓰고 주간 요약은
  한국어로 받는 사용자가 있다. 처음 설치 때만 `llmLanguage` 기본값을 UI 판정 언어로 맞춘다.
- 리포트 프롬프트·근거 라벨("커밋 N건")·요일 표기(`report.ts` `WEEKDAY`)는 **모델 입력**이라 번역하지 않는다.
  UI에 보이는 요일·기간 라벨(잔디·상단 바)만 `fmtWeekday`·`fmtPeriodLabel`로 바꾼다 — 같은 배열을 두 용도로
  쓰고 있으니 이행 때 갈라야 한다.
- 리포트 편집 패널의 자리표시자 도움말(`REPORT_PROMPT_VARS.desc`)은 UI라 번역한다. 토큰(`{언어}` 등)은
  사용자가 저장한 프롬프트와의 호환 때문에 **바꾸지 않는다**.

## 5. 검증 장치 — 이 설계의 핵심

2,000개를 여러 단계에 걸쳐 옮기면 "다 옮겼다"는 말을 믿을 수단이 있어야 한다. 셋을 겹친다.

### 5.1 컴파일러

- 키 누락·여분·인자 불일치 → `tsc --noEmit` 오류(`defineText`의 `TextShape`).
- 언어 누락 → TS는 `Record<Exclude<Locale,"ko">, …>`, Rust는 `match` 망라성.
- 이 둘은 **이미 옮긴 문구**의 정합만 지킨다. 안 옮긴 한글 리터럴은 컴파일러가 모른다 → §5.2.

### 5.2 소스 스캔 가드 (한글 재유입 금지)

- **구현(P0)**: e2e 66(`tests/e2e/suites/66-i18n.mjs`)이 스캐너(`tests/e2e/lib/i18n-scan.mjs`)로 `src/`를 읽어
  주석을 걷고, 한글이 남은 파일 목록을 기준 목록 `tests/e2e/i18n-legacy-files.json`과 대조한다. 목록에 없는
  파일에 한글이 있으면(새 파일·이행 끝난 파일에 재유입) 빨강, 목록에 있는데 한글이 사라진 파일도 빨강 —
  **목록은 줄어들기만 한다.** "이행 끝난 경로 목록을 늘린다" 대신 이렇게 뒤집은 이유: 새 파일이 저절로 검사
  대상이 되고, 기준 목록이 곧 남은 일의 목록이다.
- 판정 단위는 파일, 기준은 "주석을 뺀 코드에 한글이 있는가"다. 문자열·JSX 텍스트를 가르는 규칙을 두지 않는다 —
  그 규칙이 틀리면 이행 끝난 파일이 정의상 0으로 나온다.
- 허용: `src/i18n/text-*.ts`(카탈로그 자체), 한 줄짜리 로그 호출(`console.*`·`logWarn` 등 — 로그는 번역하지
  않는다), 줄 끝 `// i18n-ok: <이유>`(정규식 속 한글·여러 줄 로그처럼 UI가 아닌 줄). LLM 프롬프트 모듈은 UI
  문구와 섞여 있어 아직 기준 목록에 있다 — 그 파일을 이행할 때 프롬프트 줄에 `i18n-ok`를 단다.
- Rust는 `lib.rs`의 기존 구조 테스트 방식(`no_poison_propagating_unwraps`처럼 소스를 읽어 단언)으로 같은
  가드를 둔다 — 이행 끝난 모듈에서 `log!` 밖의 한글 리터럴 금지.
- **반증 절(필수)**: 가드를 처음 켤 때 이행된 파일 하나에 한글 리터럴을 일부러 넣어 빨개지는지 확인하고
  되돌린다(이 저장소의 "결함이 있어도 통과하는 단언" 교훈 — 주석 제거가 틀리면 정의상 0이 나온다).

### 5.3 영어 스윕 e2e (화면에 한글이 남았는가)

- 스위트 하나가 `uiLanguage="en"`으로 바꾸고 주요 화면을 순회한다: 메인(사이드바·툴바·변경·diff·로그)·
  설정 전 카테고리·리포트·모아보기·리소스 모니터·각 편집기·확인 대화상자·빈 상태.
- 화면마다 보이는 텍스트 노드와 `title`·`placeholder`·`aria-label`을 모아 **한글이 있으면 빨강**. 사용자 데이터
  (프로젝트명·파일명·커밋 메시지)는 픽스처를 ASCII로 만들어 오탐을 없앤다.
- 같은 순회에서 버튼·라벨 넘침(`scrollWidth > clientWidth + 1`)을 경고로 모은다(§4.5).
- 끝나면 원래 언어로 되돌린다(스위트가 설정을 덮으면 finally에서 복구 — 48 ⑧b와 같은 규약).
- 소스 스캔(§5.2)이 "코드에 남은 한글", 영어 스윕이 "화면에 새는 한글(Rust 오류·조립된 문구 포함)"을 잡는다 — 서로 못 보는 것을 본다.

### 5.4 기존 e2e는 한국어로 고정

- 샤드 드라이버(`shard.mjs`)가 각 샤드의 데이터 디렉터리 설정에 `uiLanguage: "ko"`를 심는다. 한국어 UI 문구를
  기대하는 249줄은 그대로 유효하다. 영어 사용자가 dev 앱으로 e2e를 돌려도 결과가 같다.
- 문구를 바꾸는 이행이 아니라 **위치만 옮기는** 이행이라 한국어 문구가 바뀌면 안 된다 — 그 자체가 회귀 검사다.
  (이행 중 한국어 원문을 다듬고 싶으면 별도 커밋으로.)

## 6. 이행 단계

각 단계는 "그 경로를 §5.2 `I18N_MIGRATED`에 올리고 가드가 초록"이 끝 조건이다. 단계 안에서는 도메인 파일
단위로 나눠 병렬로 옮길 수 있다(도메인 파일이 갈라져 있어 충돌하지 않는다).

| 단계 | 범위 | 규모(한글 줄) | 끝 조건 |
|---|---|---|---|
| **P0 기반** | `define-text`·`messages`·`useMessages`·형식 헬퍼 · `uiLanguage` 설정·Rust `i18n.rs`·OS 판정·`ui_language_resolved` · 진입점 언어 선적용 · 가드 2종 뼈대(+반증) · 영어 스윕 뼈대 · 용어집 · 샤드 `uiLanguage=ko` 고정 | — | 설정에서 언어를 바꾸면 모든 창이 재시작 없이 바뀐다(빈 카탈로그로) |
| **P1 뼈대 UI** | 타이틀바·툴바·사이드바·공통(`common`)·토스트/확인 대화상자·설정 화면 전체·`stores` | ~480 | 앱을 켜서 처음 보이는 화면과 설정이 영어 |
| **P2 Git 작업** | 변경·diff·워크스페이스·로그/히스토리·파일 트리·커밋 폼·Git 대화상자·리포트 UI | ~340 | 일상 Git 흐름이 영어 |
| **P3 터미널·보조 창** | 모아보기·터미널·메모장·폴더/즐겨찾기·리소스 모니터·PDF | ~400 | |
| **P4 도구·편집기** | DB·API 클라이언트·이미지 편집기(656)·동영상(339) | ~1,140 | 가장 크다 — 도메인 파일을 잘게(편집기 패널별) |

- **P1~P4 동안 영어는 "English (베타 — 일부 한국어)"로 노출**한다. 옮기지 않은 화면이 한국어로 섞여 나온다는
  사실을 선택 상자에서 먼저 알린다. P5에서 표시를 뗀다.
- 한 단계는 대개 한 회차(수백 줄)다. 기계적 추출은 에이전트에 맡기되, 번역은 용어집을 붙여 한 번에 한
  도메인씩 — 도메인 간 용어가 흔들리는 것이 가장 흔한 실패다.
- 새 기능은 P0 이후 **처음부터** 카탈로그로 쓴다(가드가 이행 경로 밖 새 파일도 막도록 P0에서 "새로 생긴
  파일은 자동으로 이행 대상"으로 둔다 — 목록에 없는 기존 파일만 예외).

## 7. 번역 작업과 용어집

- `DOCS/i18n-glossary.md`를 P0에서 먼저 만든다. 앱 고유 용어(모아보기=Aggregate view, 잔디=activity heatmap,
  메모장, 탭 모으기, float 모드, 패널 분리, 히스토리, 즐겨찾기 폴더, 리포트, 체크포인트 등)와 Git 표준 용어
  (stage/unstage·discard·amend — Git 공식 영어를 따른다)를 한 번 정한다.
- 영어 문체: 버튼은 동사 원형(Save·Discard), 확인 대화상자는 질문형, 문장 끝 마침표는 완결 문장에만.
- 번역은 LLM 배치(용어집 첨부) → 사람이 도메인 단위로 훑는다. 영어 스윕 스크린샷이 검토 자료다.
- 번역 품질 문제는 **컴파일러도 가드도 못 잡는다** — 그래서 용어집과 단계별 스크린샷 검토가 유일한 장치다.

## 9. 대안과 기각 이유

| 대안 | 기각 이유 |
|---|---|
| i18next + react-i18next | 문자열 키(`t("a.b")`)라 조립·오타가 런타임에만 드러난다. 타입 안전은 추가 설정·생성 단계가 필요하고, ICU·백엔드 로더 등 쓰지 않을 기능이 딸려 온다 |
| Lingui / FormatJS(추출형) | 빌드 파이프라인에 추출·컴파일 단계가 붙는다. 원문을 코드에 두는 방식이라 영어 전환 시 대량 diff |
| 언어별 파일(`ko.ts`·`en.ts` 통짜) | 한쪽만 고치는 표류, 여러 세션이 한 파일을 두고 충돌. 도메인 파일 안에 나란히 두는 쪽이 낫다 |
| IpcError에 키+인자 → 프런트 번역 | IPC를 안 타는 출력(창 제목·OS 알림·health 사유) 해결 못 함. 오류 생성 475곳 구조 변경. stderr 혼합 메시지 처리 복잡 |
| Rust Fluent(`.ftl`) | 새 파일 형식·의존성·런타임 조회(키 문자열). `match` 함수로 컴파일 시점 망라성을 얻는 쪽이 이 저장소 기준에 맞다 |
| 런타임 폴백(없는 번역은 한국어로) | "일단 뜨게" 하면 빠진 번역이 영영 드러나지 않는다. 컴파일 오류로 막는다(이행 중 혼재는 가드 범위로 관리) |

## 10. 결정이 필요한 것

1. **대상 언어** — 영어만(권장, 먼저) / 일본어·중국어까지. 구조는 같고 번역·검토 비용만 언어 수에 비례한다.
2. **기본값** — `"system"`(권장: OS가 한국어면 지금과 동일) / `"ko"` 고정.
3. **이행 중 영어 노출** — "베타" 표시로 P1부터 노출(권장) / P5 끝날 때까지 숨김.
4. **로그 언어** — 사용자 문구를 그대로 쓰는 안(권장, §4.4) / 로그는 항상 한국어.
5. **웹사이트** — 이번 범위 밖(권장) / 함께.

| 단계 | 결과 |
|---|---|
| P0 기반 | 설정 `uiLanguage`·Rust 판정(`i18n.rs`)·`ui_language_resolved`·카탈로그 뼈대·첫 렌더 전 언어 확정·가드 2종·용어집 |

| P5 Rust | 47개 파일 → `crate::i18n::text_{db,files,tools,system,git_net}` — 함수 하나 = 문구 하나, 모든 `Lang` match |
| 가드 | 프런트 e2e 66(기준 목록 177→10) · Rust `user_facing_korean_lives_in_i18n_modules`(기준 목록 4) — 둘 다 반증 확인 |
| 영어 순회 e2e 67 | 첫 회차에 누출 2건(지난 세션 배너 문구가 시작 언어로 굳음 · `toLocaleString()` 무인자 4곳)을 잡아 고침. 설정 8개 섹션도 돈다 |
| 리베이스 후 마감 | 태스크 72(STT·자막)와 겹친 파일 이관 — 프런트 22개(도메인 `captions` 신설, `settings`·`media`·`lib` 확장), Rust 15개(`text_video`·`text_stt` 신설). 기준 목록 **양쪽 0** — 이제 어떤 파일이든 한국어 UI 문구가 들어오면 가드가 빨갛다 |
| 마감 항목 | NSIS `["Korean", "English"]` + `displayLanguageSelector: false` · 영어 "베타" 표기 제거 · 언어를 바꾸면 떠 있는 보조 창(터미널·리소스 모니터·모아보기·캡쳐) 제목을 다시 씀(`retitle_aux_windows`) · 원문 오타 "브라우저은" 수정 |

**이관하며 정한 것**
- 모델 비고(`ModelSpec.note`)는 const 카탈로그 안이라 문자열로는 언어를 못 고른다 → 문구 함수 포인터
  (`fn() -> &'static str`)를 담는다. 부를 때 `(m.note)()`.
- 설정 검색 색인은 label·keywords를 카탈로그로 옮기고, 검색은 **모든 언어**의 label·keywords를 본다
  ("prompt"·"프롬프트" 둘 다 찾힌다).
- 설정 › AI의 "테스트" 프롬프트는 화면에 보이는 문장 그대로 모델에 보낸다 — 영어 UI면 영어 문장.
  (§4.6 "LLM 프롬프트는 번역하지 않는다"의 예외: 보이는 문구와 보내는 문구가 같은 경우)
- 디스크에 새로 만드는 파일 이름(`… (변환).mp4`)은 UI 언어를 따른다 — "새 폴더"와 같은 선례.
- 스토어에 저장된 오류 문구·토스트는 만든 순간의 언어로 남는다(§4.2).
- e2e 는 한국어로 돈다 — 스위트가 찾는 한국어 원문은 한 글자도 바꾸지 않았다(이관 에이전트들이 번들로 대조).
- 스캐너(e2e 66)는 정규식 리터럴을 모른다 — 정규식 속 따옴표를 `\x22`로 쓰고 주석 몇 줄에 `i18n-ok`를 달아 피했다.

**후속(범위 밖)**
- 한국어 판정을 쓰는 e2e(64·65 의 Rust 오류 정규식 등)는 영어 UI 로 돌리면 깨진다 — e2e 는 샤드가 `uiLanguage=ko` 로 고정하므로 문제없다.
- 동영상 편집기·자막 패널은 영어 순회(67)가 돌지 않는다(영상 픽스처·ffmpeg 필요) — 소스 가드(66)만 지킨다.
