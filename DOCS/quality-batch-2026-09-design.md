## A. 복사·붙여넣기 — "무슨 일이 있어도 된다"

### A.1 현황(근거)

태스크 65가 터미널 복사를 고치며 만든 계층 쓰기가 `src/lib/clipboard.ts` 에 있다:
플러그인 → 웹뷰(`navigator.clipboard`) → `execCommand` + **6회 재시도(40~80ms 백오프)** + 되읽기 검증 +
사유 있는 토스트(`clipboard.ts:76-145`).

**문제는 그 문을 안 지나는 호출부가 6곳이라는 것이다**(확인):

| 위치 | 파일:줄 | 무엇을 복사 |
|---|---|---|
| 로그 목록 | `CommitList.tsx:18-23` | 커밋 해시·메시지 |
| 커밋 상세 | `CommitDetailPane.tsx:14-19` | 해시·메시지 |
| 변경 패널 | `ChangesPanel.tsx:442-447` | 경로·파일명 |
| 파일 트리 | `FileTreePanel.tsx:553-558` | 경로·상대경로·이름 |
| 사이드바 | `ProjectList.tsx:331-338` | 프로젝트 경로 |
| 리소스 모니터 | `SysMonitorWindow.tsx:353-358` | PID·경로 |

여섯 곳 모두 `@tauri-apps/plugin-clipboard-manager` 의 `writeText` 를 **직접** 부르는 같은 4줄 사본이다 —
재시도 0 · 폴백 0 · 사유 없는 고정 문구 · 로그 0. Windows 클립보드 경합(Win+V 히스토리·RDP rdpclip·
Ditto·KVM)과 Linux 플러그인 영구 실패(`tauri-plugin-clipboard-manager` 가 arboard 인스턴스를 1회만 만든다)가
**여기서는 그대로 살아 있다.** 사용 빈도는 터미널 복사와 맞먹는다(해시 복사·경로 복사).

그 밖에 확인된 것:

- **이미지 복사는 재시도가 없다** — `ImageEditor.tsx:1767-1775` 의 `writeImage` 1회 시도. 같은 경합 때문에
  Rust 화면 캡처는 이미 8회 백오프를 넣어 뒀다(`capture.rs:530-541`).
- **붙여넣기는 실패 신호가 0개다** — `pasteIntoTerminal` 의 `catch { /* noop */ }`(`terminal.ts:335-337`),
  Linux `term_paste` 는 타임아웃 2초와 "클립보드가 빔"을 **둘 다 빈 문자열**로 돌려준다(`terminal.rs:718-719`).
  사용자에겐 "눌렀는데 아무 일도 안 일어남"으로 보이고 로그도 없다.
- **결과를 버리는 `void copyText(...)` 3곳** — `ImageEditor.tsx:2022`, `clipboard.ts:220,230`.
- **화면 잠금(LogonUI) 중에는 세 단계가 전부 실패한다**(실측: e2e 5건, `DOCS/pdf-viewer-editor-design.md:871-877`).
  코드에 그 상황을 구분하는 분기는 없다.
- macOS 비-ASCII(한글·이모지)는 웹뷰 경로를 의도적으로 건너뛴다(MacRoman 이중 인코딩 방지, `clipboard.ts:94`) —
  즉 **mac 한글 복사의 폴백 단계는 0개**다. 트레이드오프이지 결함은 아니지만 문서에 남긴다.
- Monaco 복사는 브라우저 기본 경로다(전용 코드 없음). Windows/Linux 에서는 계층 폴백 밖.
- **선택 스냅샷(마우스 추적 모드 스태시)은 공유 자원이다** — [복사]뿐 아니라 모아보기 셀의
  [선택 영역 번역]도 같은 `snapshotSelection` 을 읽는다(`AggregateTerminals.tsx:917-918`).
  스위트 52 는 스태시 비움을 [복사] 관점에서만 단언하므로 번역 쪽 회귀는 안 잡힌다(확인).

### A.3 설계

```ts
// src/lib/clipboard.ts — 추가되는 공개 표면(기존 copyText 시그니처 불변)
export async function copyText(text: string): Promise<boolean>;      // 기존
export async function copyImage(bytes: Uint8Array): Promise<boolean>; // 신규 — 8회 백오프
export function lastCopyFailure(): string;                            // 기존
export function copyFailMessage(): string;                            // 기존
```

- **호출부 교체(6곳)**: `void writeText(x)` → `void copyOrToast(x)` 헬퍼 하나로 통일한다. 헬퍼는
  `copyText` + 성공/실패 토스트(`copyFailMessage()`)를 담는다 — 6곳이 각자 토스트 문구를 갖지 않게.
- **ESLint 게이트**(A-K2): `no-restricted-imports` 에 `@tauri-apps/plugin-clipboard-manager` 를 넣고
  `src/lib/clipboard.ts` 만 예외. 위반 시 빌드 전 `npm run lint` 에서 잡힌다.
- **붙여넣기 신호**(A-K4·A-K5):

  | 상황 | 지금 | 바뀐 뒤 |
  |---|---|---|
  | 클립보드가 빔 | 무음 | 토스트 "클립보드가 비어 있습니다" (info) |
  | Linux 2초 타임아웃 | 무음(빈 문자열) | 토스트 "클립보드 소유자가 응답하지 않습니다" + [다시 시도] |
  | 플러그인/OS 오류 | 무음 | 사유 토스트 + 로그 |
- **잠금 감지**: 별도 API 는 쓰지 않는다. 플러그인 오류 문자열에 `not accessible`·`being held` 가 있으면
  "다른 프로그램이 클립보드를 쓰고 있습니다 — 다시 시도하세요"(기존 문구 재사용), Windows 에서 세 단계가
  **모두** 실패하면 "화면이 잠겨 있으면 클립보드를 쓸 수 없습니다"를 덧붙인다(추정 근거: 잠금 중 실측 실패 5건).

## B. 인코딩 — 어떤 코드 파일에서도 한글이 깨지지 않게

### B.1 현황(근거) — 깨지는 지점은 한 줄이다

사용자 사례(CP949 `.h` 주석)를 바이트로 역추적했다. `"일반 사용"` 의 CP949 바이트 `C0 CF B9 DD 20 BB E7 BF EB`
를 UTF-8 로 lossy 디코드하면 정확히 `�Ϲ� ���` 가 나온다 — 사용자가 본 문자열과 **문자 단위로 일치**한다
(`"멀티비전(예약)"`·`"연결검사"` 도 동일 확인).

```rust
// src-tauri/src/commands/diff.rs:198-199  ← 여기서 원본 바이트가 파괴된다
old_content: old_bytes.map(|b| String::from_utf8_lossy(&b).into_owned()),
new_content: new_bytes.map(|b| String::from_utf8_lossy(&b).into_owned()),
```

사슬(확인): `diff.rs:65` 파일 바이트 읽기(손실 0) → `diff.rs:181-184` `looks_binary` 는 **NUL 바이트만** 보므로
CP949 는 텍스트로 통과 → `:198` `from_utf8_lossy` 가 유효하지 않은 바이트를 `U+FFFD` 로 **치환**(비가역) →
프론트(`DiffViewer.tsx:369`)는 이미 복구 불가능한 문자열을 받는다.

**저장은 더 나쁘다(데이터 유실 경로).** 에디터 저장은 `write_file(content: String)` 한 곳으로만 가고
(`tree.rs:70-88`), 그대로 UTF-8 바이트를 쓴다. 즉 **CP949 파일을 열어 한 글자만 고치고 저장하면 한글 주석이
`EF BF BD`(U+FFFD) 로 영구 기록**된다. 완화 요소는 "내용이 안 바뀌면 저장 안 함"(`DiffViewer.tsx:456`) 하나뿐이고,
`formatOnSave` 가 켜져 있으면 편집 없이도 발동할 수 있다.

그 밖에(확인):

- 저장소에 **인코딩 관련 크레이트가 없다** — `encoding_rs`·`chardetng` 모두 없음. BOM 처리 0건.
- 같은 결함의 형제: 검색 결과(`search.rs:104`), 심볼·정의(`tree.rs:972,1098,1331`),
  심볼 시그니처는 `read_to_string` 이라 **비-UTF8 파일에서 통째로 빈다**(`tree.rs:1182,1514`).
- git 러너는 죄가 없다 — stdout 을 `Vec<u8>` 로 보존하고 호출자가 디코드를 고른다(`runner.rs:18-28`).
- UTF-16 파일은 NUL 때문에 "바이너리"로 빠진다. UTF-8 BOM 은 그대로 첫 글자로 들어간다(추정: 방어 코드 부재).
- 프론트에 인코딩 개념이 없다 — `FileDiff` 타입에 필드 없음(`ipc.ts:67`), 상태바에 표시 없음.
- 비-UTF8 픽스처·회귀 스위트 0건.

### B.3 설계

## D. git changes·log 속도

### D.1 현황(근거)

"동시성이 아니라 절대 시간이 문제이고, 지배 요인은 `-uall` 의 IO 와 레포마다 도는 `rev-parse --git-dir`"라고

| ② | 워처 1건이 **전 프로젝트** status 를 무효화(`["statuses"]` 통째) | `events.ts:131` |
