## Anti-Patterns Verdict

**슬롭인가**: 아니다. 이 패널은 도메인을 아는 사람이 손으로 만든 물건이다. 키프레임 스냅을 숨기지 않고 공개하고, copy/encode 비호환을 조용히 강등하지 않고 이유와 함께 전환하며, GIF 무구간 경고를 미리 띄우고, Windows invoke 응답 유실까지 견디는 종결 계약을 갖고 있다. LosslessCut 사용자라면 이 지점들을 알아보고 긴장을 푼다.

문제는 미학이 아니라 **표면 계약**이다. 컨트롤 세 개가 자기가 말하는 일을 하지 않는다.

**결정론적 스캔**: 실행 불가. `detect.mjs`는 shim이고 실제 엔진(`detect-antipatterns.mjs`)이 설치본에 없다. 두 번의 실제 시도 모두 `Error: bundled detector not found.` exit 1. `find ~/.claude -name "detect-antipatterns.mjs"` 결과 0건. findings 0건은 "깨끗함"이 아니라 데이터 부재다.

**시각 오버레이**: 없음. 대상이 Tauri 웹뷰라 스킬의 live-server + `detect.js` 주입 경로가 적용되지 않는다. 대신 실행 중인 dev 앱에 CDP(29222)로 직접 붙어 실측했다. 사용자 스크린샷의 바로 그 파일(`cam03_접착제도포_2.mp4`, 1:01:09.9, 492x1356, 11.17fps)을 문서 창으로 열어 패널을 마운트하고, 구간 설정·틱 2개·2x 배속·빈 파일명 등 각 분기를 실제로 구동했다. 측정 후 창을 닫고 device metrics를 복구해 앱 상태는 원복했다.

실측 축이 내 브리핑의 오류 두 건을 반박했다. 정정한다: 영역 버튼은 아이콘 전용이 아니라 텍스트("영역")를 갖고, 폴더 입력은 `<label>`로 감싸여 있어 접근 가능한 이름이 있다. 진짜 무명 필드는 파일명 입력 하나뿐이다.

## Overall Impression

**엔진은 훌륭하고 계기판이 거짓말을 한다.**

분할 로직은 검증했다. 1시간 영상에 틱 2개면 정확히 3개 파일이 폴더 하나에 들어간다. 프로세스 위생, 이벤트/프라미스 경주, 언마운트를 견디는 배치 스토어까지 이 카테고리 평균보다 낫다.

그런데 그 위에 얹힌 UI가 세 번 거짓말한다. **형식**은 형식을 정하지 않고, **화질**은 이미 encode로 바뀐 뒤에도 "무손실 복사"를 계속 표시하며, **분할 저장**은 바로 위 다섯 개 컨트롤을 통째로 버린다. 세 개 모두 조용하다. 경고도, 에러도, 사후 안내도 없다.

가장 큰 기회는 새 기능이 아니다. 패널이 실제로 할 일을 말하게 만드는 것이다. 대부분 문자열 한두 줄과 조건절 하나짜리 수정이다.

## What's Working

**타임라인 마커 시스템.** 앰버 틱 라인 + 시각 배지, 드래그 이동, 우클릭 삭제, 휠 줌/팬 상태에서도 정확한 좌표, 화면 밖 마커를 살려주는 미니맵, 배지가 겹치면 라벨만 버리고 라인과 히트 타깃은 남기는 N개 일반화 규칙(`VideoPlayer.tsx:1041-1047`). 장식이 하나도 없다. Resolve/LosslessCut 사용자가 즉시 신뢰할 물건이다.

**실패 모델이 정직하다.** 헤더 주석(`:3-4`)이 "침묵 전환 금지"를 설계 결정으로 못박고 실제로 지킨다. ffmpeg 부재 상태는 에러 문자열이 아니라 "설정 열기" 버튼이 달린 진짜 복구 화면이다.

**분할 라벨이 입력이 아니라 결과를 보고한다.** "틱 2개 → 3개 파일"은 `planSegments`에서 파생되므로(`:287`) 100ms 병합이나 꼬리 절삭이 일어나도 라벨이 거짓이 되지 않는다.

## Priority Issues

### [P0] 형식 select가 출력 형식을 결정하지 않는다

- **무엇**: `buildSpec`(`:212-226`)에 `format` 필드가 없다. 백엔드는 `outRel`의 확장자로 muxer를 고른다(`video.rs:510` `muxer_for_ext(&ext)`). 형식 select는 추천 파일명과 어떤 컨트롤을 보여줄지만 바꾼다. 사용자가 파일명을 한 번 손대면(`nameEditedRef`, `:407`) 추천이 동결되므로(`:135-137`), 그 뒤 GIF를 골라도 이름은 `.mp4`로 남고 mp4가 생성된다. 드롭다운은 GIF라고 표시한 채로.
- **왜 중요한가**: 표시값이 디스크의 결과물과 모순될 수 있는 컨트롤이다. 에러도 경고도 없다. 이 카테고리 어떤 도구도 이러지 않는다. 한 번 겪으면 패널의 다른 컨트롤도 못 믿게 된다.
- **고칠 것**: `format` 변경 시 파일명의 확장자를 강제로 다시 쓴다. `:392`의 onChange를 아래로 바꾼다.
  `(e) => { const f = e.target.value as Format; setFormat(f); const ext = f === "gif" ? "gif" : f === "audio" ? aud.ext : "mp4"; setName((n) => n.replace(/\.[^.]+$/, "") + "." + ext); }`
  이러면 사용자가 이름을 편집했든 아니든 형식이 항상 권위를 갖는다.
- **명령**: `/impeccable harden`

### [P0] 분할 저장이 바로 위 다섯 컨트롤을 조용히 버린다

- **무엇**: `videoSplit.ts:227-240`이 세그먼트 스펙을 `speed: null, crop: null, maxHeight: null, removeAudio: false, crf: 23`으로 하드코딩한다. `startSplit`(`:493-501`)에 넘어가는 건 folder/mode/stem/durationMs/hasAudio뿐이다. 그동안 배속·화질·해상도·영역·오디오 제거는 전부 활성 상태로 두 줄 위에 앉아 있다(`disabled={busy}`의 `busy`는 단일 내보내기만 추적한다).
- **왜 중요한가**: 해상도 720p와 영역을 지정하고 분할 저장을 누르면, 정직한 진행률 바를 보고, 성공 토스트를 받고, 원본 해상도의 크롭 안 된 파일 3개를 얻는다. 모든 가시 신호가 설정이 적용됐다고 말했다. 짜증을 불신으로 바꾸는 실패다.
- **고칠 것**: `:553` 뒤에 형제 경고 블록을 추가하고, `:459`의 카운트 span 뒤에 실제 범위를 붙인다.
- **명령**: `/impeccable harden`

### [P0] 내보내기가 첫 렌더부터 죽어 있고, 이유에 도달할 수 없다

- **무엇**: 기본 상태(mp4 + 무손실 복사 + 무구간 + 무음소거)가 `nothingToDo`(`:209`)를 만족한다. 패널이 열리는 순간 주 액션이 흐려진다. 유일한 설명은 disabled 버튼의 `title`(`:432`)이다.
- **왜 중요한가**: 세 겹으로 도달 불가다. (1) Chromium/WebView2는 disabled 컨트롤에 포인터 이벤트를 보내지 않아 툴팁이 뜨지 않는다. (2) 실측: `el.focus()` 후 `document.activeElement` 비교 결과 `focusable: false`. 키보드 사용자는 탭으로 지나쳐 버린다. (3) 실측 대비 2.23:1(accent 20% 배경 + `disabled:opacity-40`, monokai 테마 실효 `#244e66` on `#060910`). 일반 텍스트 4.5:1을 2배 차이로, UI 컴포넌트 3:1도 못 넘는다. 분할 저장도 동일 구조로 2.23:1이다. 주 액션 세 개 중 둘이 대기 상태에서 판독 불가다.
- **고칠 것**: `:423`의 `{!busy ? (` 직전에 이유를 인라인으로 렌더한다. 대비는 `disabled:opacity-40`을 `disabled:bg-transparent disabled:text-fg-dim disabled:border disabled:border-edge`로 교체해 해결한다. 흐림이 아니라 위계 강등으로.
- **명령**: `/impeccable clarify` 다음 `/impeccable audit`

## Minor Observations

- "수 초 어긋날 수 있음"은 두 자릿수 과장이다. 설계 문서 자신의 실측(`DOCS/task/22-video-timetick-split.md:335`)이 틱 25/17/20s에 대해 25.01/17.02/20.02를 기록했다. 약 0.02초다.
- 같은 힌트가 "재인코딩"이라는, 화질 메뉴에 없는 값을 고르라고 지시한다. 실제 옵션은 무손실 복사 / 원본급 / 표준 / 압축이다(`:338-341`).
- 화질 select는 `forcesEncode`로 mode가 encode가 되고 CRF 23이 적용된 뒤에도 "무손실 복사"를 계속 표시한다(`:114-118`, `:221`).
- 형식(부모)이 화질·해상도·영역·오디오 제거(자식) 아래 줄에 렌더된다. `:388-402`를 `:297` 행의 첫 자식으로 옮기면 로직 변경 없이 해결된다.
- 프레임 버튼이 파일명 입력과 내보내기 사이에 끼어 있어 그 설정을 쓰는 것처럼 보이지만, 파일명·구간·영역·해상도를 전부 무시한다(`:255-281`).
- GIF는 컨트롤이 하나도 없는데(전부 mp4 게이트 뒤) 패널은 파일이 매우 커질 수 있다고 경고한다(`:558-562`). 해결 수단을 화면에서 제거한 채 하는 경고다.
- "오디오만 (mp3)"이 배속 변경만으로 "오디오만 (m4a)"로 바뀐다(`:399`).
- `selCls`(`:30`)가 모든 select에 `text-fg-muted`를 준다. 정작 하중 있는 내용은 select의 값인데 옆의 정적 라벨보다 흐리게 읽힌다.
- 틱 지우기가 확인도 undo도 없이 전부 지운다. 최소한 title에 개수를 넣어라.
- 폭 340px 미만에서 앱 전체 가로 스크롤이 시작된다(`body.scrollWidth` 346). 720px에서 첫 줄바꿈, 420px에서 높이가 두 배 이상. 데스크톱 앱이라 실무 영향은 낮다.
- em dash에 대하여: impeccable의 공유 규칙은 UI 카피에서 긴 대시를 금지한다. 이 패널과 프로젝트 전반은 이를 절 구분자로 일관되게 쓴다. 한국어 UI에서 통용되는 용법이고 일관성이 있으므로 결함으로 올리지 않는다. 규칙을 적용하려면 전역으로, 별도 커밋으로 하라.

## Questions to Consider

- 분할 저장이 In/Out 구간을 존중해야 하는가? `planSegments(ticks, probe.durationMs / 1000)`(`:287`)은 항상 전체 길이를 덮는다. 구간 안에 틱을 찍어도 클립은 1시간 전체를 커버한다.
- 분할 행의 "정확한 지점에서 분할(재인코딩)" 체크박스와 내보내기 행의 화질 select는 같은 개념인가? 같은 소스에 대해 copy 대 CRF 23을 고르는 일을 같은 패널에서 다른 단어와 다른 위젯으로 두 번 묻는다.
- `.copy` 접미사가 디스크에 도달할 일이 있는가? `parts`가 비었을 때만 생성되는데(`:132`) 그건 정확히 내보내기가 차단되는 `nothingToDo` 상태다.
- 패널 설정이 `key={path}` 리마운트로 파일마다 초기화되는 게 맞는가? 카메라 파일 열 개를 분할하는 사용자는 폴더 이름을 열 번 다시 친다.
